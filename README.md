# University Room Fund

Информационная система для учёта аудиторного фонда университета.

Приложение позволяет вести сведения о корпусах, помещениях и подразделениях, рассчитывать общую площадь и вместимость помещений. Система предоставляет веб-интерфейс и HTTP API.

## Назначение системы

Система предназначена для:

- учёта корпусов университета;
- учёта аудиторий и других помещений;
- учёта подразделений;
- хранения площади и вместимости помещений;
- получения сводной информации об аудиторном фонде;
- предотвращения появления некорректных и дублирующихся записей.

## Категории пользователей

### Неавторизованный пользователь

Может:

- открыть страницу входа;
- зарегистрировать учётную запись;
- войти в систему;
- проверить доступность сервиса через служебный адрес.

### Авторизованный пользователь

Может:

- просматривать сведения об аудиторном фонде;
- создавать, изменять и удалять корпуса;
- создавать, изменять и удалять подразделения;
- создавать, изменять и удалять помещения;
- просматривать сводные показатели;
- выполнять поиск;
- выйти из системы.

## Основные сценарии

1. Пользователь регистрирует учётную запись.
2. Пользователь входит в систему.
3. Пользователь добавляет корпус.
4. Пользователь добавляет подразделение.
5. Пользователь создаёт помещение и связывает его с корпусом и подразделением.
6. Пользователь просматривает общую площадь и вместимость помещений.
7. Пользователь изменяет или удаляет существующие записи.
8. Пользователь выходит из системы.

## Правила предметной области

- Номер помещения должен быть уникальным внутри одного корпуса.
- Помещение обязательно должно относиться к существующему корпусу.
- Подразделение, указанное для помещения, должно существовать.
- Площадь помещения должна быть положительным числом.
- Вместимость помещения не может быть отрицательной.
- Операции с аудиторным фондом доступны только авторизованным пользователям.
- Пароли пользователей не хранятся в открытом виде.

## Основные сущности

### Building — корпус

| Поле | Назначение |
| --- | --- |
| `id` | Уникальный идентификатор |
| `name` | Название корпуса |
| `address` | Адрес корпуса |

### Department — подразделение

| Поле | Назначение |
| --- | --- |
| `id` | Уникальный идентификатор |
| `name` | Название подразделения |

### Room — помещение

| Поле | Назначение |
| --- | --- |
| `id` | Уникальный идентификатор |
| `number` | Номер помещения |
| `area` | Площадь помещения в м² |
| `capacity` | Вместимость помещения |
| `building_id` | Идентификатор корпуса |
| `department_id` | Идентификатор подразделения |

### User — пользователь

| Поле | Назначение |
| --- | --- |
| `id` | Уникальный идентификатор |
| `username` | Уникальный логин |
| `password_hash` | Хеш пароля |

## Связи между сущностями

- один корпус может содержать несколько помещений;
- одно подразделение может использовать несколько помещений;
- каждое помещение относится к одному корпусу;
- каждое помещение связано с подразделением.

## Установка и запуск

### 1. Создание виртуального окружения

```powershell
python -m venv .venv
```

### 2. Активация виртуального окружения в PowerShell

```powershell
.venv\Scripts\Activate.ps1
```

### 3. Установка зависимостей

```powershell
python -m pip install -r requirements.txt
```

### 4. Создание локального файла настроек

```powershell
Copy-Item .env.example .env
```

После копирования укажите в `.env` правильные параметры подключения к PostgreSQL и значение `SESSION_SECRET`.

### 5. Запуск приложения

```powershell
python -m uvicorn app.main:app --reload
```

После запуска доступны:

- веб-интерфейс: <http://127.0.0.1:8000/>;
- документация Swagger: <http://127.0.0.1:8000/docs>;
- схема OpenAPI: <http://127.0.0.1:8000/openapi.json>;
- проверка работоспособности: <http://127.0.0.1:8000/health>.

## Аутентификация

В приложении используется серверная аутентификация на основе сессии.

После успешного входа сервер сохраняет идентификатор пользователя в подписанной cookie сессии. Пароли сохраняются в базе данных только в виде хеша PBKDF2-SHA256.

Неавторизованный запрос к защищённым операциям возвращает статус `401 Unauthorized`.

## HTTP API

### Аутентификация

| Метод | Адрес | Назначение |
| --- | --- | --- |
| `POST` | `/auth/register` | Регистрация пользователя |
| `POST` | `/auth/login` | Вход в систему |
| `POST` | `/auth/logout` | Выход из системы |
| `GET` | `/auth/me` | Получение текущего пользователя |

### Корпуса

| Метод | Адрес | Назначение |
| --- | --- | --- |
| `GET` | `/buildings` | Получить список корпусов |
| `POST` | `/buildings` | Создать корпус |
| `GET` | `/buildings/{building_id}` | Получить корпус |
| `PUT` | `/buildings/{building_id}` | Изменить корпус |
| `DELETE` | `/buildings/{building_id}` | Удалить корпус |
| `GET` | `/buildings/{building_id}/rooms` | Получить помещения корпуса |

### Подразделения

| Метод | Адрес | Назначение |
| --- | --- | --- |
| `GET` | `/departments` | Получить список подразделений |
| `POST` | `/departments` | Создать подразделение |
| `GET` | `/departments/{department_id}` | Получить подразделение |
| `PUT` | `/departments/{department_id}` | Изменить подразделение |
| `DELETE` | `/departments/{department_id}` | Удалить подразделение |

### Помещения

| Метод | Адрес | Назначение |
| --- | --- | --- |
| `GET` | `/rooms` | Получить список помещений |
| `POST` | `/rooms` | Создать помещение |
| `GET` | `/rooms/{room_id}` | Получить помещение |
| `PUT` | `/rooms/{room_id}` | Изменить помещение |
| `DELETE` | `/rooms/{room_id}` | Удалить помещение |

Полное интерактивное описание запросов и моделей доступно по адресу `/docs`.

## Обработка ошибок

API использует стандартные HTTP-коды:

| Код | Значение |
| --- | --- |
| `200` | Запрос выполнен успешно |
| `201` | Запись создана |
| `400` | Нарушено правило предметной области |
| `401` | Пользователь не авторизован |
| `404` | Запись не найдена |
| `409` | Конфликт или дублирование записи |
| `422` | Ошибка проверки входных данных |

Ответ с ошибкой содержит поле `detail` с описанием причины.

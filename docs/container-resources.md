# ЛР4. Обоснование ограничений ресурсов

## Назначение

Ограничения ресурсов предотвращают неконтролируемое
потребление CPU, RAM и количества процессов контейнерами.

## Приложение FastAPI

- Лимит CPU: 0.5 ядра.
- Лимит RAM: 256 MiB.
- Лимит процессов: 100.

При контрольном наблюдении приложение использовало
примерно 53 MiB оперативной памяти.

Лимит 256 MiB обеспечивает запас для обработки запросов,
загрузки библиотек и кратковременных увеличений нагрузки.

Ограничение 0.5 CPU подходит для учебного приложения
с небольшой нагрузкой. Для промышленной эксплуатации
потребовались бы нагрузочные испытания.

## PostgreSQL

- Лимит CPU: 1 ядро.
- Лимит RAM: 512 MiB.
- Лимит процессов: 100.

При контрольном наблюдении PostgreSQL использовал
примерно 25 MiB оперативной памяти.

Лимит 512 MiB оставляет запас для работы с запросами,
кеширования данных и операций обслуживания базы.

## Сервис миграций

- Лимит CPU: 0.5 ядра.
- Лимит RAM: 256 MiB.

Миграции выполняются отдельным кратковременным процессом.
Для небольшого учебного проекта указанных ресурсов
достаточно при проверенной текущей схеме БД.

## Контроль

Используемые команды:

docker stats --no-stream
docker compose ps -a
make container-check

Ограничения проверяются автоматически в Docker Compose.

Приведенные лимиты подходят для лабораторной среды.
Они не являются результатом полноценного нагрузочного
тестирования и должны пересматриваться при росте нагрузки.
